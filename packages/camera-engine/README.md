# Standalone camera engine (AGPL-3.0-only)

This independently built camera program uses the InstaDarts inference pipeline and project-owned pretrained models at the pinned commit in upstream.json. It exchanges documented JSON messages with a parent page; it does not import Dartbracket code, sessions, game rules or database clients. It has no network write access. All application authentication, permission checks and game writes belong to the separate host application.

Source: https://github.com/Instadarts/instadarts/tree/a455d7f8c5c7df2b37f7d08fefac970ec9e74ea0

Upstream files: src/client/vision, src/shared/vision, boardGeometry, media, scoring, types, settings, config, scorerStorage and scorerPower. Copyright retained under LICENSE. Modifications by Dartbracket contributors: local runtime/model URLs, shared digital crop in frame.ts, minimal appConfig/e2e adapters. entry.ts, index.html and build.mjs are additional AGPL-3.0-only integration code. Model inference and calibration algorithms are upstream's, not newly trained models.

Build with Node 22+: `npm ci --include=dev && npm run build`. Both model files in models/ and the two reference photographs in reference/ are committed to this repository and SHA-256 verified against upstream.json. Building never downloads assets from the original project and never depends on its availability. Missing or changed assets fail the build; restore them from this repository. npm dependencies still need installation (or an existing npm cache). Models are also included exactly once in the complete source download. Build outputs go to ../../public/camera-engine; adjust `out` in build.mjs for independent hosting. LiteRT is Apache-2.0; its npm package supplies the WASM runtime. The package lock pins all dependencies.

Protocol: trusted same-origin parent sends `{channel:'dartbracket-camera',type:'start'|'stop'|'config',config:{zoom, lens, model, camera, run}}`. Engine posts `{channel:'dartbracket-camera',type:'state',data:{frameId,status,error,located,tips,image,preview,cameras,ms,frames,imageRevision}}`. x/y are upstream integer board coordinates, y-up, center 500000, with board width 451mm. A null/unlocated result is never an empty-board result. Digital zoom changes the same crop used by inference, motion and previews. Rectified JPEGs use a 510mm square so the outer double radius occupies one third of image width, matching the host image contract.

Users can download this program's complete corresponding source, including adapter and model weights, from the footer. Do not remove the license, notices or source offer. No claim of guaranteed E-dart compatibility or measured accuracy is made. Test actual devices/boards before competitive use.

Reference test images were obtained from the same pinned commit, are committed locally and SHA-256 verified, and are included in the corresponding-source archive. LiteRT JavaScript/WASM is provided by Google under Apache-2.0; see THIRD_PARTY_NOTICES.txt and APACHE-2.0.txt.

The setup preview is sampled about once per second. Evidence images use the saved inference input and update only after two observations agree on a changed dart count, including removal. imageRevision identifies that evidence independently from preview updates. Up to 16 chronological observations in frames preserve intermediate throws between transport polls. Zoom supports 1–5× with native zoom followed by any necessary digital crop.

Device optimization reuses the pinned upstream onboarding.ts and onboardingHarness.ts. It measures motion and all available preprocessing/inference combinations, validates both reference photographs, and caches only validated choices per browser/camera/model/retest revision. profile.ts adapts cancellation and preserves the remotely selected model. visionRuntime.ts additionally discards results invalidated by motion and retains triggers arriving while inference is busy. Motion thresholds remain the upstream defaults. Continuous forced inference has been removed; only settled motion, targeted confirmations and a gated recovery watchdog request passes.

Camera-engine tests: from the application repository run `npx vitest run --config packages/camera-engine/vitest.config.mts`. The archive includes the upstream onboarding decision tests and additional motion-race tests.

Latency adapter: frame messages include on-device movement-to-observation durations and a local wall-clock start timestamp; the separate host calibrates clocks and transports them. Coordinate messages are posted before photo rectification. Evidence copies the exact input before yielding, renders cooperatively, and rejects work after camera/geometry changes. New-dart confirmations wait 80ms; confirmed empty-board handling retains its existing >=250ms safeguard and 300ms follow-up. Motion thresholds and model code are unchanged.
